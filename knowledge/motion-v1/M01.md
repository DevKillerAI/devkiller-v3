# Motion visual design: React shared-layout collections and accessible expansion
Original DevKiller guidance, 2026-09-20. Eligible: React Complete and Next static export.
Use motion/react for purposeful transitions between related UI states. Plan one memorable interaction around the domain, such as expanding a collection into its contents; retain clear typography, real images and working actions. The referenced iOS folder is inspiration, not a reusable paid template. Motion+ source is not included.
Implementation recipe: render a keyboard-operable button for each collection with a unique stable ID. Use the same unique layoutId on its compact and expanded surface; AnimatePresence owns conditional exit. Keep selection in application state. Compose an accessible Dialog for focus trapping, Escape and restoring focus to the trigger. Never replace dialog semantics with a clickable div. Use MotionConfig reducedMotion='user'; useReducedMotion can replace spatial movement with a brief opacity transition. Do not animate dialog transforms with two libraries. Scope IDs per collection and avoid duplicate layoutId instances outside the intended transition.
Next: place hooks and motion components in a client component; no browser access during module evaluation. Test rapid open/close, keyboard-only use, resize, reduced motion and route changes. Expanded content must remain readable and actionable without animation. Keep the library useful when no cards exist.
Sources: https://motion.dev/examples/react-ios-app-folder (paid full source; visual reference only); https://motion.dev/docs/react-layout-animations ; https://motion.dev/docs/react-use-reduced-motion
