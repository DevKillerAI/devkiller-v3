# Visual QA for motion, Three.js and material effects
DevKiller curated review checklist, 2026-09-23. Use during visual-review; distinguish a real defect from an optional taste preference.

## Evidence first
Render the app at a representative desktop size and a narrow mobile size. Review the actual browser output, not only source code or a successful build. Record viewport, route/state and visible evidence. Inspect one static initial frame and relevant interactive states. Respect reduced-motion settings.

## Motion checks
Motion clarifies an action or narrative beat; the user can still read and operate the app if motion is skipped. No content flashes in late, controls move away from the pointer, focus disappears, scroll is hijacked, or layout changes cause overlap. Check reduced motion, keyboard, touch and repeated interactions. If the animation is decoration with no visible purpose, simplify it.

## 3D/material checks
The intended object is immediately identifiable and has a deliberate camera/composition. Check contrast against its background, visible lighting direction, form at thumbnail size, responsive crop, frame rate, loading/failure fallback and pointer/keyboard parity. For glass specifically, require visible environmental reflections and visible transmitted/distorted background; transparency without an environment often reads as dark/flat. Reject an opaque black sphere presented as glass. For metal require readable highlights and non-flat form. For a requested “3D” scene, a static flat CSS circle is not sufficient unless clearly chosen as fallback.

## Repair order
Correct missing scene/environment/material setup first; then framing, contrast, silhouette, responsive sizing and motion. Reduce expensive post-processing before deleting meaningful design detail. Do not add unrelated effects to conceal the defect. Re-render and compare against the same acceptance checklist. A repaired build is not done until the repaired visual state is inspected.
