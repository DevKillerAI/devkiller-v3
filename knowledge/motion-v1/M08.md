# Product-specific art direction for generated apps and sites
DevKiller curated visual-design playbook, 2026-09-23. Applies to planning, component design and visual review across supported stacks. It is guidance, not a fixed brand theme.

## Create a direction, not a template
Before implementation, state the audience, product category, primary task, emotional tone and viewing context. Select a distinct visual thesis and 2–3 signature motifs that support it. Specify typography roles, palette with contrast pairs, spacing/radius rhythm, image/illustration treatment, navigation form, content density and one interaction signature. Explain why the chosen imagery belongs to this product. Never default to the same pale background, centered hero, three cards and generic dashboard for every request.

## Design the working product
Map the information hierarchy and key user journey before decorating. Choose page composition that fits the domain: editorial, workspace, catalog, timeline, canvas, map, control room or another purposeful pattern. Use real components and useful empty/loading/error states. Distinguish a marketing site from an operational app. Use semantic theme tokens so the chosen direction is consistent and can be changed without restyling each component independently.

## Use effects with restraint and proof
Choose 3D, animation, SVG or photography only when it communicates product value. Treat 3D as a focal visual with a defined camera/light/material brief, animation as feedback or narrative, SVG as diagrams/illustrations/icons, and photography as literal subject evidence. Do not substitute generic screenshots for relevant product imagery or handmade SVGs for realistic products. Preserve attribution and fallback behavior.

## Review across the actual viewport
Inspect a rendered desktop and mobile view. Check hierarchy at first glance, type scale/line lengths, contrast, spacing, image relevance/crop, alignment, control states, responsive rearrangement and motion. Fix obvious defects before adding effects. If the brief asks for a specific style, verify the visible output against it; compiling is not visual approval.
