# Motion for React: interaction, scroll choreography and reduced motion
DevKiller curated implementation playbook, 2026-09-23. Sources are official Motion documentation. Eligible for React Complete and Next static-export client components; verify the active stack before importing.

## Choose the motion by user intent
- Use `whileHover` and `whileTap` for brief feedback on a real interactive control. Keep buttons and links semantic; add a visible `whileFocus` state when focus is not already clear.
- Use `whileInView` for a one-time reveal that helps establish reading order. Set `viewport={{ once: true }}` for editorial entrance effects. Keep content visible when JavaScript is unavailable or motion is reduced.
- Use `useScroll` + `useTransform` only when a value should continuously track scroll (for example a thin reading-progress line or restrained image parallax). Choose offsets against the section being narrated; do not animate every block or make scroll control essential content.
- Use `layout` for meaningful reflow/reorder and `layoutId` for one shared object moving between two related states. Use `AnimatePresence` for conditional exit. Make IDs unique and preserve a normal, readable state if animation is interrupted.
- Use variants when parent and child motions need one authored sequence. Prefer a small number of coordinated values over a cascade of arbitrary delays.

## Make the visual feel intentional
Define the before/after state, the focal object, the reason for movement, and its duration/easing before writing JSX. Motion should clarify hierarchy or feedback, never compensate for weak layout. Choose one motion signature per screen; avoid simultaneous scale, blur, parallax and rotation on the same element. Do not let two animation systems own the same element/property.

## React implementation safeguards
Import React APIs from `motion/react`. Keep browser-only hooks in a client component in Next. Use `MotionConfig reducedMotion="user"` and `useReducedMotion()` to replace spatial movement with opacity or no decorative motion. Never hide essential content until an animation callback. Avoid high-frequency React state updates for continuously changing values; use MotionValues/styles. Keep clickable area and keyboard behavior unchanged during movement.

## Acceptance checks
Test the initial render without animation, keyboard focus, tap/hover, rapid repeated toggles, resize, route exit, and `prefers-reduced-motion`. Confirm no text shifts under the pointer, clipped content, layout jump, duplicated shared IDs or action blocked by animation. Capture the final state at desktop and mobile widths.
