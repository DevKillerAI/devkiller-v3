# Three.js visual components: spatial art direction, lifecycle and performance validation
Original DevKiller guidance, 2026-09-20. Installed three 0.186.0 on all extended profiles; React/Next also provide Fiber/Drei.
Select 3D when it explains an object, space, configuration or material. Do not make a routine form a 3D scene. Plan camera framing, light direction, background contrast, material roughness and a useful interaction before coding. Use approved model assets or intentional procedural geometry. Do not draw crude products and present them as real photos. Always keep essential product facts and actions in normal HTML.
Use a sized container, responsive camera aspect and renderer size, and cap pixel ratio. Prefer demand rendering for a static scene. Provide visible HTML fallback for unavailable WebGL/loading failure. Reduce motion by disabling automatic camera orbit while preserving manual controls. Use keyboard-accessible HTML controls with the same state as the scene. React/Next use Canvas with an error boundary and a client boundary in Next; Vue/Angular instantiate after mount and own cleanup. Dispose geometries, materials and textures; remove resize observers/listeners and cancel frame loops. Avoid downloading invented model URLs.
Validate resize, mobile readability, state updates from controls, fallback without WebGL, cleanup after route change and repeated mounts. Animation is enhancement: forms, navigation and persistence must work without it. No performance or premium-quality claim without examining the rendered result.
Sources: https://threejs.org/docs/ ; https://threejs.org/manual/#en/cleanup ; https://r3f.docs.pmnd.rs/advanced/scaling-performance
