# S04 — Multi-screen apps with HashRouter / navegação rotas recarregar voltar

react-v3 allows react-router-dom 7.18.3. Use HashRouter for this static preview environment. It keeps routing after # so reloading a deep route does not request a nonexistent server file. Hosting migration can reconsider routing later; do not require a new server now.

Authored skeleton:
```jsx
import {HashRouter,Routes,Route,NavLink} from 'react-router-dom';
function App(){return <HashRouter>
  <nav aria-label="Workspace"><NavLink to="/">Studio</NavLink><NavLink to="/library">Library</NavLink></nav>
  <Routes><Route path="/" element={<Studio/>}/><Route path="/library" element={<Library/>}/>
    <Route path="*" element={<p>Page not found. Use the navigation to return.</p>}/></Routes>
</HashRouter>}
```
Keep shared project state and persistence above route elements so navigating doesn't reset unsaved work. Use NavLink active state for orientation. Use route parameters for entity views when appropriate. Don't call router hooks outside the provider. Avoid wrapping each page in another router. Do not import framework/server APIs or request loaders that don't exist.

An ordinary one-page site needs no router; section navigation can use scrollIntoView. Don't mix HashRouter URLs with unrelated #section anchors. Focus the new page heading when appropriate and ensure back/forward work. Missing entity IDs should show a human-readable empty state rather than crash.

Verify navigation, refresh on #/library, browser back and forward, shared state persistence and a fallback route. Database saving remains explicit and asynchronous, independent of navigation. Source consulted 2026-09-14: https://reactrouter.com/api/declarative-routers/HashRouter . Authored integration example.
