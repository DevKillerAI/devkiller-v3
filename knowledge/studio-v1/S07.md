# S07 — Responsive app shell: no white bars / controles móveis faixas brancas display contents

Use para prevenir o problema observado no ROOMLAB: três botões móveis sem estilo e o X da biblioteca apareciam no desktop. A causa verificada foi agrupar .mobile-bar, .mobile-panel-head e .drawer-wrap em display:contents. Essa propriedade remove a caixa do elemento, mas mantém seus filhos visíveis. Não significa ocultar.

Padrão autoral mínimo para a shell (adaptar breakpoint):
```css
.mobile-bar,.mobile-panel-head{display:none}
.drawer-wrap{display:contents}
[hidden]{display:none!important}
button{font:inherit;color:inherit}
@media(max-width:760px){
  .mobile-bar{display:flex;gap:.5rem;background:var(--surface);padding:.5rem}
  .mobile-bar button{background:var(--surface);color:var(--text);border:1px solid var(--border);min-height:44px}
  .mobile-panel-head{display:flex;align-items:center;justify-content:space-between}
  .mobile-panel-head button{background:transparent;color:var(--text);border:0;min-width:44px;min-height:44px}
  .drawer-wrap{display:none}
  .drawer-wrap.open{display:block;position:fixed;inset:0;z-index:50}
}
```
O wrapper e os controles têm funções diferentes. Em react-v3, preferir Radix Dialog para drawer com foco, Escape e retorno ao trigger; ainda é necessário CSS e o trigger continua exclusivo do breakpoint certo. Não usar controles brancos padrão sobre texto branco. Não esconder um menu inteiro para disfarçar um botão sem função.

No desktop: ações essenciais visíveis, botões móveis ausentes. No celular: trigger visível, painel fechado inicialmente, abre por toque/teclado e fecha com Escape/ação explícita. Redimensionar não pode deixar overlay invisível prendendo cliques. Testar com texto longo, zoom e viewport estreito; um pixel de diferença não é uma reprovação funcional.
