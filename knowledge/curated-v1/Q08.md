# Q08 — shadcn registry blocks: complete components and stack compatibility

Scope: react-v3; design and integration reference only, not permission to add dependencies. Sources checked 2026-09-16: https://ui.shadcn.com/docs/registry and https://github.com/shadcn-ui/ui/blob/main/LICENSE.md . The shadcn/ui repository has an MIT license; this does not establish the license of every third-party registry or paid block collection.

A registry distributes source files together with metadata and dependencies. Preserve that unit when preparing reusable components. Do not index a JSX fragment without its stylesheet, imports and required files. Keep upstream URL, revision, license notice and adaptation notes with each imported example.

Engine compatibility: the current profile provides React, radix-ui, motion, Recharts, Lucide and React Router. It does not provide Tailwind or arbitrary shadcn dependencies. Copying utility-class markup alone will produce incomplete styling. Adapt a selected layout to complete plain CSS and installed imports, then compile and inspect it before marking it reusable. Never claim that a fetched block is already installed.

Design application: select composition according to audience and workflow. A customer storefront emphasizes discovery and product details; an operator workspace emphasizes density and actions. Vary page structure with editorial image/text, tables, detail panels and timelines when appropriate. Do not reduce every page to the same dashboard cards. Keep real product content and meaningful states, not just decorative components. A reusable block is a starting point, not proof of application completeness.
