# Q06 — React Router navigation, route reload and responsive workspace

Scope: react-v3. Source checked 2026-09-16: https://reactrouter.com/api/declarative-routers/HashRouter . Original synthesis for the Engine static preview environment.

HashRouter keeps the application location in the URL fragment. This suits static preview hosting where arbitrary server routes are not supplied. Use installed react-router-dom imports and one router boundary. Link navigation should preserve browser history; reserve buttons for actions. Include an unknown-route state instead of a blank screen.

Engine application: separate catalog, reservations, analytics and settings when the brief requires them. Directly reload a nested route and verify the intended view returns after persisted data loads. A sidebar selected state must reflect the actual route. Mobile navigation should expose the same destinations and close after selection, while retaining keyboard access and visible labels. Do not hide every label through a global CSS rule. Prefer a two-column workspace on large screens and a deliberate mobile flow; a smaller version of the desktop canvas is not responsive design.

Check back/forward, reload, empty states and a missing record route. Never present links to features that are not implemented.
