# PostgreSQL backend migrations, transaction integrity and isolation
OPTIONAL REAL BACKEND: When requested functionality needs server-side validation, shared multi-user state, transactions or a relational database, deliver src/server/routes.mjs exporting default async function register(app,{db}). app is a Fastify instance scoped to /api; define routes such as app.get('/items', async()=>...). Frontend calls fetch('/api/items'). db is a pg Pool connected to a persistent, isolated PostgreSQL database for this project, never exposed to the browser. Deliver ordered migrations src/server/migrations/001_initial.sql etc. Migrations run transactionally once and are immutable: append later migrations, never rewrite applied ones. Use parameterized SQL ($1,$2), schema validation, pagination and transactions with SELECT FOR UPDATE or constraints for stock/bookings. Always release acquired clients in finally. Return real errors and status codes; await commits before confirming. No secrets in source, no listen() or process startup in routes. Helpers may be .mjs in src/server/. Only backend imports pg, zod and node builtins. Do not use window.DevKillerDB for records owned by PostgreSQL. Lightweight apps may instead use the existing DevKillerDB service. Auth/payments/third-party credentials are not provisioned automatically: never simulate them. Backend is private local preview infrastructure, not production tenant authentication.
Use explicit validation on the server, not only in forms. Treat simultaneous requests as normal. Protect inventory with row locks inside a transaction. Use unique constraints for invariants and idempotency keys for duplicate submissions. Never expose database URLs or SQL errors to browsers. Migration failures must stop the candidate, preserve the previous preview and report the failing migration. Frontend success means a committed server result. QA uses a different schema from live data.
Sources: https://www.postgresql.org/docs/current/tutorial-transactions.html ; https://fastify.dev/docs/latest/Reference/Routes/
