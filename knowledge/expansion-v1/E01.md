# Official shadcn components, real 3D and complex data interfaces
OFFICIAL COMPONENT REGISTRY: shadcn/ui source components are supplied automatically when imported from @/components/ui/<name>. Available: button, input, textarea, label, card, badge, separator, skeleton, dialog, alert-dialog, select, tabs, dropdown-menu, popover, tooltip, sheet, checkbox, switch, table, accordion, progress, scroll-area, avatar. Use their standard named exports. Do not regenerate these primitives; compose domain-specific UI around them. @/lib/utils supplies cn(). Source is copied into the project and remains editable/exportable. A token stylesheet is supplied; customize CSS variables for the requested art direction. Import @import "tailwindcss"; at the start of src/styles.css. shadcn is not an importable npm package.
ADDITIONAL INSTALLED LIBRARIES: three, three/addons/*, @react-three/fiber (Canvas/useFrame), @react-three/drei, @tanstack/react-query (QueryClientProvider required), @tanstack/react-table v8. Use only where needed. Three.js must dispose resources and handle unavailable WebGL with a usable fallback; explicit canvas dimensions; respect reduced motion, no uncontrolled permanent animation. R3F Canvas needs an error boundary. Use simple procedural geometry unless approved assets are supplied; do not invent model URLs. Prefer conventional layout for ordinary content, not a 3D scene everywhere. Table and charts must reflect saved data. React Query must invalidate related queries after successful mutations.
Sources: https://ui.shadcn.com/docs/registry ; https://r3f.docs.pmnd.rs/getting-started/introduction ; https://tanstack.com/table/v8/docs/guide/introduction
