# React Pro forms validation with React Hook Form and Zod

Supported only in react-v4. Checked 2026-09-16. Libraries installed: react-hook-form 7.88.0, @hookform/resolvers 5.9.1, zod 3.25.76. This is Zod 3; do not assume Zod 4-only methods. Primary reference: https://github.com/react-hook-form/resolvers

Complete minimal form component; compose it into the requested app. Persistence uses the supplied Engine API, not localStorage. Load existing records before allowing edits. Keep date/stock business rules in separate tested domain helpers. Form validation alone cannot provide transactional multi-user stock control.

```jsx
import {useRef,useState} from 'react';
import {useForm} from 'react-hook-form';
import {zodResolver} from '@hookform/resolvers/zod';
import {z} from 'zod';
const schema=z.object({quantity:z.number().int().min(1,'Choose at least one item')});
export default function QuantityForm(){
 const lock=useRef(false),[notice,setNotice]=useState('');
 const {register,handleSubmit,formState:{errors,isSubmitting}}=useForm({resolver:zodResolver(schema),defaultValues:{quantity:1}});
 const save=async data=>{if(lock.current)return;lock.current=true;setNotice('');try{await window.DevKillerDB.set('quantity',data.quantity);setNotice('Saved')}catch{setNotice('Could not save. Your entries are preserved.')}finally{lock.current=false}};
 return <form onSubmit={handleSubmit(save)} noValidate>
  <label htmlFor="quantity">Quantity</label>
  <input id="quantity" type="number" {...register('quantity',{valueAsNumber:true})} aria-invalid={!!errors.quantity} aria-describedby="quantity-error"/>
  <p id="quantity-error" role="alert">{errors.quantity?.message}</p>
  <button disabled={isSubmitting}>Save</button><p role="status">{notice}</p>
 </form>;
}
```

Use Controller for controlled Radix Select; never spread register onto a non-native control without adapting value/onChange. Preserve draft and dialog on save failure. An empty numeric input produces NaN rather than a meaningful zero: show a friendly error. Optional business details can use editable placeholders; missing optional content should not block the preview. Verify invalid input, keyboard focus, successful save/reload, failed save, and repeated submission.
