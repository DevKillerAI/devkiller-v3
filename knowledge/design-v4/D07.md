# D07 — Site para evento sem data, local ou descrição: preencher depois, A definir

Aplicável a pedidos em português como: “Crie um site para meu evento; ainda não tenho data, endereço, descrição nem imagem, quero preencher depois”. Também serve para empresa, perfil ou catálogo com informações incompletas. Conteúdo ausente não é erro de geração nem motivo para impedir preview.

Preservar o nome do evento e todos os dados fornecidos. Usar null nos dados ausentes e mostrar “A definir” em português ou “To be defined” no idioma inglês padrão. Não inventar endereço, telefone, data, preço, depoimento ou fotografia como verdade. Uma área com SVG local pode representar imagem ainda não fornecida.

Incluir uma área Editar informações / Edit details no aplicativo, com campos para completar nome, descrição, data e local quando estiverem pendentes. Carregar o banco DevKillerDB antes de habilitar edição. Se a leitura falhar, mostrar erro e nova tentativa; nunca tratar falha como ausência de dados. Salvar com await DevKillerDB.set e só confirmar depois. Recarregar deve preservar as alterações.

Exemplo de dados: {name: nomeFornecido, description: null, date: null, venue: null}. Ao renderizar, usar valor?.trim() || 'A definir'. O texto provisório pertence à apresentação, não a um cálculo. Data ausente não inicia contagem regressiva. Preço ausente não significa ingresso grátis. Local ausente não gera mapa falso. Explicar junto à ação dependente o campo necessário e oferecer caminho para editar. O restante do site permanece utilizável.

Se faltar regra que altera o funcionamento, registrar essa decisão pendente sem inventar a resposta. Não transformar qualquer conteúdo faltante em obrigação de perguntar antes de criar. Explicar no resumo o que pode ser preenchido depois. Implementar a edição de verdade; ela é local, não painel protegido com autenticação.

QA: conferir preservação do nome fornecido, placeholder legível, edição e persistência após recarregar. Não exigir uma data ou endereço que o usuário não informou. A falta editorial é uma limitação explicada; botão quebrado ou falha ao salvar continua sendo defeito funcional.
