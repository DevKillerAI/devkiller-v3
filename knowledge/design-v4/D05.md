# D05 — Coherent SVG icons and accessible controls / ícones Lucide sem emojis

Use for navigation, actions, categories, empty states and status indicators. Icons should clarify a label and share one visual family, rather than appear as unrelated emojis. In react-v2, lucide-react is already available. In other stacks use authored inline SVG without importing an unsupported library.

Example with existing dependencies:
```jsx
import {Plus, Check, ChevronDown} from 'lucide-react';
<button type="button" aria-label={`Add ${artist.name} to my schedule`}>
  <Plus size={20} strokeWidth={1.75} aria-hidden="true"/>
</button>
```
Use explicit accessible names on icon-only buttons. An icon accompanying visible text is normally decorative; avoid duplicating the label for assistive technology. Pick consistent optical size and stroke weight across the application, center inside a comfortable button and keep visible focus. Hover styling should not be the only indication of an action. Selected state needs text or a check indicator as well as color. Set pointer-events:none on a decorative icon if it sits above a real input; do not cover the clickable input with an intercepting overlay.

Custom SVG is useful for a distinctive logo or subject-specific symbol. Start from simple shapes with a common viewBox and rounded joins where appropriate; compare visual weight at the actual rendered size. Do not replace photos with pictograms or a meaningful status with a vague decorative symbol. Use the library's published exports, not guessed icon names that may break compilation. Abstract hero art and functional icons have different design goals.

Source consulted 2026-09-14: https://lucide.dev/how-to/accessibility
Also uses the local DevKiller react-v2 dependency contract. This guidance does not install new icon libraries or validate generated import names automatically.
