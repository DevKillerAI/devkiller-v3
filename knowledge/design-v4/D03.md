# D03 — Responsive cards: prevent text/button overlap / espaçamento rótulos longos

Use for artist cards, schedules, products, toolbars and any heading with an adjacent action. A label and its add button require separate layout tracks. Do not absolutely position the action on top of text. The card grows when content wraps.

Authored CSS pattern:
```css
.card-head { display:grid; grid-template-columns:minmax(0,1fr) auto; gap:1rem; align-items:start; }
.card-meta { min-width:0; margin:0; overflow-wrap:anywhere; line-height:1.5; }
.card-action { inline-size:2.75rem; min-block-size:2.75rem; padding:.5rem; }
.card-action svg { width:1.25rem; height:1.25rem; pointer-events:none; }
.cards { display:grid; grid-template-columns:repeat(auto-fit,minmax(min(100%,16rem),1fr)); gap:1rem; }
.card { padding:clamp(1rem,2vw,1.5rem); }
button:focus-visible, a:focus-visible { outline:2px solid var(--accent); outline-offset:4px; }
```
Use a native button with an accessible name such as “Add Ava Meridian to my schedule”, not only “+”. Put the full stage/genre label in card-meta and the button in card-action. Avoid fixed card heights and arbitrary negative margins. Do not solve collision by reducing all typography or hiding meaningful words. Long translations, 200% zoom and narrow columns are normal content cases. A one-pixel rounding difference by itself is not a functional defect.

Verification: render short and long labels at 320, 391, 768 and 1440 CSS pixels; compare visible bounds of label and action for overlap, check the page is not horizontally overflowing, and click the action. Test focus separately. Decorative overlays must not receive pointer events. A screenshot reveals composition, while a successful click demonstrates an action; neither alone proves the other.
