# D02 — Premium themed filters, dropdowns and navigation / menus seletores cores

Use for festival genre filters, category pickers, catalogs, navigation and dark/light branded sites. Treat the expanded options as part of the design, not only the closed trigger. Match surface, text, border, accent, radius, spacing and shadow tokens. Give selected options a checkmark or radio plus text; hover, focus and selected are distinct.

Choice of pattern: a few choices suit styled radio chips; a longer set suits a disclosure panel with native radios and a Done button. A native select remains useful in ordinary forms, but its OS popup is not fully controlled by appearance:none. Set the correct color-scheme and select/option foreground/background. A brand-critical filter should prefer the styled disclosure pattern, within allowed dependencies. Do not import shadcn, Radix or other unavailable packages just because a tutorial uses them.

An authored React skeleton (adapt labels, spacing, data and placement):
```jsx
function Filter({label, options, value, onChange}) {
  const [open, setOpen] = useState(false);
  const id = useId(), root = useRef(null), trigger = useRef(null);
  const close = () => { setOpen(false); trigger.current?.focus(); };
  useEffect(() => {
    const outside = e => { if (!root.current?.contains(e.target)) setOpen(false); };
    document.addEventListener('pointerdown', outside);
    return () => document.removeEventListener('pointerdown', outside);
  }, []);
  return <div ref={root} className="filter"
    onBlur={e => {if (!e.currentTarget.contains(e.relatedTarget)) setOpen(false);}}
    onKeyDown={e => {if (e.key === 'Escape' && open) {e.preventDefault(); close();}}}>
    <button ref={trigger} type="button" aria-expanded={open} aria-controls={id}
      onClick={() => setOpen(!open)}>{label}: {options.find(o=>o.id===value)?.label} ▾</button>
    {open && <div id={id} className="filter-panel">
      <fieldset><legend>{label}</legend>{options.map(o =>
        <label key={o.id} className="filter-option"><input type="radio" name={id}
          value={o.id} checked={value===o.id} onChange={()=>onChange(o.id)}/>{o.label}</label>
      )}</fieldset><button type="button" onClick={close}>Done</button>
    </div>}
  </div>;
}
```
Import useState/useId/useRef/useEffect from React. Each instance owns its radio name. Keep real inputs keyboard accessible; style accent-color and label:has(input:checked). Tab enters/leaves; arrows select within the radio group; Space selects; Escape/Done closes and restores trigger focus. Keep the panel open during arrow navigation. Click-away must not steal focus from the outside target. Use an inline expanding panel for reliable containment, or explicitly measure available space for a floating panel. Set max-block-size and overflow:auto; never clip the panel under an ancestor's overflow:hidden. Use opaque surfaces. Size buttons for comfortable touch and visible focus. Native radios avoid a half-implemented ARIA listbox.

Navigation is a different component: nav with real links and disclosure buttons, aria-expanded, current-page indication, Escape and click-away. A mobile drawer needs a close action and should not rely on hover. Ordinary site navigation is not role=menu. Motion can be subtle and disabled under prefers-reduced-motion.
